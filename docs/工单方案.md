## 二、工单详情

### T-01 Agent 维度进度事件流打通 `P0` 0.5d

**目标**：让 Orchestrator 的执行过程可被前端实时观测。

**背景**：`Orchestrator._emit()` 已发出 `planning / planned / dispatching / collecting /
auditing / revision` 等事件，并携带 `agent` / `step` / `total` 字段；
但 `Worker` 目前调用 `agent.run()` 时**未传 `on_progress`**，事件全部丢弃。

**范围**：
- `src/api/worker.py`：构造进度回调，将事件写入 Redis 进度通道（如 `agent:progress:{task_id}`，
  List 结构，TTL 与任务一致）；
- `src/api/main.py`：新增 `GET /api/task/{task_id}/progress` 端点，返回事件数组；
- 事件结构统一为 `{stage, agent, step, total, status, ts}`。

**验收标准**：
- [ ] 提交任一任务后，`GET /api/task/{id}/progress` 返回按时间递增的事件序列；
- [ ] 三步任务（图片→文本→视频）的事件序列中，能看到 `image_agent` / `writer_agent` /
      `video_agent` 依次 dispatch 与 collect；
- [ ] 任务终态后进度记录自动过期清理，不占内存与 Redis。

**风险**：低。纯增量改动，不影响任务执行主链路。

### T-02 前端多 Agent 协作链路面板 `P0` 1.5d

**目标**：观测看板从「模型调用链」升级为「多 Agent 协作视图」，这是答辩演示的核心亮点。

**范围**：
- `frontend/src/api/task.ts`：新增 `getTaskProgress(taskId)`；
- `frontend/src/components/inspector/AgentInspector.tsx`：
  - 新增 **Agent 协作时间轴**：按步骤展示 `Orchestrator → WriterAgent → ReviewerAgent → …`
    的消息流向与状态（复用 T-01 的事件流）；
  - 保留现有「多智能体调用链」区块（模型级），二者上下并列：上层看 Agent 协作，下层看模型调用；
  - 审查打回（`revision` 事件）以醒目样式标注，演示「反思重试闭环」。
- `frontend/src/stores/taskStore.ts`：轮询过程中累积事件到 `progressEvents`。

**验收标准**：
- [ ] 执行多步任务时，右栏实时出现 Agent 协作时间轴，逐个点亮；
- [ ] 时间轴与聊天区产物一一对应（图片卡片 ↔ ImageAgent 节点）；
- [ ] 审查打回场景能在时间轴上看到重试点与打回原因；
- [ ] 刷新页面后仍可从后端恢复时间轴（进度已持久化于 Redis）。

**依赖**：T-01
**风险**：低。前端纯增量，不改现有布局。

### T-03 视频产物本地化归档 `P0` 1d

**目标**：解决视频链接 24 小时过期导致答辩现场演示失败的风险。

**背景**：硅基流动返回的是带签名的 S3 临时链接（`X-Amz-Expires=86400`）。
一周前生成的视频在答辩时已失效——这是**演示可靠性事故**。

**范围**：
- 新增 `data/videos/` 归档目录；
- `src/core/agents/video_agent.py`（或 Worker 侧）：任务成功后下载视频到本地，
  以 `{task_id}_{step}.mp4` 命名，同时在 `Artifact.metadata` 写入
  `{"local_path": "data/videos/xxx.mp4"}`；
- `src/api/main.py`：新增 `GET /api/artifacts/video/{name}` 静态托管端点，支持 Range 请求；
- 前端气泡：优先使用本地 URL，失败时回退原始外链。

**验收标准**：
- [ ] 生成视频后 `data/videos/` 出现对应文件，大小与远端一致；
- [ ] 模拟签名过期后，本地 URL 仍可播放；
- [ ] 浏览器拖动进度条不卡顿（Range 请求生效）。

**风险**：中。需处理下载失败、超大文件、并发写同名，建议加锁与大小上限。

### T-04 Reviewer 严格度校准 `P1` 1d

**目标**：解决 Reviewer 误判导致反思闭环无法收敛的问题。

**现象**：实测中，事实正确的文本（如「长城始建于春秋战国」）也被打回，
理由为「长城不是世界最早建筑」。若在闭环中反复打回，会白白耗尽重试预算并浪费 Token。

**范围**：
- 抽样构造评测集（正确/错误各 30 条），量化当前误报率；
- 调整审查 Prompt：强调「不要吹毛求疵，仅在存在实质性问题时打回」；
- 引入分级：`score >= 4` 直接通过；`3 <= score < 4` 通过但记 warning；`< 3` 打回；
- 阈值配置化到 `config/app.yaml`，便于论文实验做参数对比。

**验收标准**：
- [ ] 评测集上误报率 < 10%（修复前基线需记录）；
- [ ] 三步链式任务不出现因审查导致的无谓重试；
- [ ] 阈值可配置，且在论文实验中记录调优过程。

**风险**：低。但**需要真实模型调用做评测**，会产生一定 Token 成本。

### T-05 快慢双车道队列 + 双 Worker `P1` 2d

**目标**：解决视频长任务阻塞文本任务的问题（毕设差异点 1）。

**现象**：当前单 Worker 串行消费。视频任务执行 5 分钟期间，
后续文本任务只能排队，导致 P95 延迟飙升。

**范围**：
- `RedisTaskManager`：新增双队列 `agent:queue:fast`（text/image）与
  `agent:queue:slow`（video），提交时按 capability 路由；
- `src/api/worker.py`：两个 Worker 实例，分别消费快/慢车道；
- 队列公平性：快车道不饿死慢车道（慢车道优先级在调度时降权）。

**验收标准**：
- [ ] 视频任务执行中，文本任务可在独立 Worker 上并发执行；
- [ ] 文本任务 P95 延迟相比单 Worker 显著下降（E2 实验验证）；
- [ ] 两车道均无任务丢失，异常可恢复。

**依赖**：T-01（需要任务类型信息透出）
**风险**：中。并发写 SQLite 需注意锁（建议开启 `busy_timeout`）。

### T-06 SSE 实时推送 `P2` 1.5d

**目标**：用服务端推送替代前端轮询，降低延迟与请求开销。

**范围**：
- FastAPI 新增 `GET /api/task/{id}/events`（`EventSource` 协议）；
- 后端从 Redis 进度通道读取并推送；任务终态后主动关闭连接；
- 前端 `EventSource` 订阅，移除轮询逻辑（保留轮询作为降级兜底）。

**验收标准**：
- [ ] 进度延迟 < 500ms（相比 2s 轮询显著提升）；
- [ ] 断线自动重连，任务不中断；
- [ ] 浏览器标签页关闭时连接正确释放。

**依赖**：T-01
**风险**：中。建议先用长轮询兜底，SSE 作为增强而非替换。

### T-07 用量与成本记录 `P2` 1d

**目标**：为论文成本对比实验提供数据支撑。

**背景**：实测单次三步任务消耗约 **¥2.10**，其中视频占 95%。
成本结构高度倾斜，是论文「成本优化」章节的关键论据。

**范围**：
- `LLMClient` 解析响应中的 `usage`（文本模型有 `prompt_tokens/completion_tokens`；
  图片/视频按张/个计数），填充 `LLMResponse`；
- `CallChainEntry` 新增 `prompt_tokens / completion_tokens / cost / latency_ms`；
- 新建 `config/pricing.yaml` 登记单价（已实测：`Z-Image-Turbo` ¥0.10/张、
  `Wan2.2-I2V` ¥2.00/个、`DeepSeek-V3` 输入 ¥0.002/K tokens、输出 ¥0.008/K tokens）；
- 前端观测看板新增「本次任务成本」卡片。

**验收标准**：
- [ ] 单次任务成本可精确到分，且与平台账单一致（抽样核对 ≥5 次）；
- [ ] 成本按 Agent/步骤分摊展示；
- [ ] 数据可供 E 组实验直接取用。

**风险**：低。需持续维护单价表（平台可能调价）。

### T-08 陈旧测试修复 `P2` 0.5d

**目标**：让 `pytest tests/` 全绿，恢复 CI 可用性。

**现状**：4 个长期失败的用例，与本次改动无关（历史遗留）：
- `test_agent.py::test_agent_fallback` — `Agent.__init__` 签名过时（少 `evaluator` 参数）；
- `test_agent.py::test_agent_fallback_success` / `test_agent_scenarios` — 依赖缺失的
  `config/model.yaml`；
- `test_api.py::test_submit_and_poll_text_task` — 依赖外部服务常驻。

**范围**：
- 修正 `Agent.__init__` 调用签名；
- 测试改为使用临时配置文件，不依赖本地 `config/model.yaml`；
- API 测试加 `skipif`（服务未启动时跳过）或改用 fixture 起服务。

**验收标准**：
- [ ] `pytest tests/` 全绿；
- [ ] 测试不产生真实 API 调用费用（或明确标记为集成测试）。

**风险**：低。
