# 多模态 AI Agent 前端优化与重构方案

## 一、方案背景与核心目标

### 1.1 背景与现状
当前前端采用 Streamlit 构建（`src/ui/app.py`）。随着项目向多 Agent 协同演进，根据 [docs/技术](docs/技术) 中的记录，现有前端面临以下深层次架构瓶颈：
- **多会话隔离缺陷**：Streamlit 依赖全局脚本单向重执行模型（Top-to-Bottom Rerun）与单一 `st.session_state`，无法在单 Tab 内实现真正的多会话状态隔离，导致历史记录易串话、需降级为单会话模式。
- **界面闪烁与输入中断**：任何局部交互（如轮询进度更新、按钮点击）均会引发全页重新渲染，导致输入框失焦、布局抖动。
- **长轮询机制开销高**：依赖 `time.sleep() + requests.get` 的 HTTP 轮询模式，时延高且徒增后端与 Redis 压力。
- **多 Agent 观测与多模态呈现能力不足**：难以优雅承载 DAG 流程图、各 Agent 实时状态（Orchestrator、Image、Writer、Reviewer）、流式打字机效果及多模态工件交互（大图灯箱预览等）。

### 1.2 重构目标
1. **彻底解决多会话隔离问题**：基于现代化前端路由与独立状态空间，实现流畅的多会话创建、切换与历史持久化。
2. **零闪烁局部更新**：基于 React 虚拟 DOM 与组件化体系，实现局部细粒度渲染。
3. **通信机制升级为 SSE（Server-Sent Events）**：将 HTTP 轮询升级为服务端事件流推送，毫秒级响应 Agent 执行流转。
4. **原生赋能多 Agent 协同体系**：提供专属的多 Agent 运行拓扑与审计面板，实时透视任务调度链路。

## 二、技术栈选型

| 层次 | 选型 | 说明 / 优势 |
| :--- | :--- | :--- |
| **构建工具** | **Vite 5+ (TypeScript)** | 秒级冷启动、极速热模块替换（HMR），开箱即用 |
| **前端框架** | **React 18 / 19** | 生态最成熟，社区中 Agent / Chat 类组件库最丰富 |
| **样式方案** | **Tailwind CSS** | 现代原子化 CSS，天然继承现有 `app.py` 中的紫色/深色系设计变量 |
| **UI 组件库** | **shadcn/ui + Lucide Icons** | 源码级可控组件（免去打包庞大第三方库），定制自由度极高 |
| **全局状态** | **Zustand** | 极轻量（<3KB），状态持久化简易，无 Context 泛滥渲染开销 |
| **通信协议** | **Axios + 原生 EventSource (SSE)** | REST 负责提交/查询，SSE 负责监听 Agent 执行事件流 |
| **流程拓扑(可选)** | **React Flow** | 用于清晰展示 Orchestrator -> Sub-Agent 的 DAG 流程与状态高亮 |

## 四、核心交互与界面设计


### 4.2 通信协议演进

#### A. RESTful 接口（保持向下兼容）
- `GET /api/sessions`：加载历史会话列表。
- `POST /api/task/submit`：提交任务并获取 `task_id`。
- `GET /api/session/{session_id}/history`：获取特定会话的历史对话记录。
- `DELETE /api/session/{session_id}/history`：清空会话历史。

#### B. SSE 实时事件流
后端在 `src/api/main.py` 提供轻量级 SSE 接口（`GET /api/task/{task_id}/events`）：
```text
event: agent_progress
data: {"agent": "Orchestrator", "stage": "PLANNING", "plan": [...]}

event: agent_progress
data: {"agent": "Image Agent", "stage": "CALLING", "model": "wanx-v1"}

event: agent_done
data: {"agent": "Image Agent", "artifact": {"type": "image", "url": "..."}}

event: task_complete
data: {"task_id": "...", "status": "SUCCESS", "results": [...]}
```
前端使用原生 `EventSource` 进行单向流式监听，实现免刷新的实时动态渲染。

### 4.3 多模态工件与质检卡片
- **Image Artifact**：骨架屏预加载、网络重试兜底、图片高保真大图弹窗。
- **Reviewer Audit Badge**：在每条助手输出旁轻量标注质量得分（如 5.0 满分标签），点击可展开审查维度（规则合规性、反思修正历史）。

## 五、分阶段实施里程碑

```text
阶段一：环境准备与通信流适配 (Phase 1)
  ├── 后端 src/api/main.py 扩展 SSE 事件推送路由
  └── 初始化 frontend 工程脚手架 (Vite + React + Tailwind + TypeScript)

阶段二：三栏骨架与会话系统打通 (Phase 2)
  ├── 实现左侧 Sidebar（会话新建、切换、删除）
  ├── 验证会话隔离性，确认根治 Streamlit 串话问题
  └── 完成主输入框交互（智能高度、快捷键防抖）

阶段三：对话流渲染与多模态工件交互 (Phase 3)
  ├── 实现消息气泡组件与 Markdown 流式渲染
  ├── 实现图片工件骨架屏与灯箱预览
  └── 对接 SSE 客户端，捕获任务全生命周期事件

阶段四：多 Agent 状态看板与联调交付 (Phase 4)
  ├── 实现右侧 Agent 运行拓扑与调用链（Call Chain）展示
  ├── 对接 Reviewer 质检结果折叠卡片
  └── 配置 Vite 反向代理联调，保留 Streamlit 为 legacy 备用
```

## 六、平滑过渡策略

- **后端免改造**：新前端全面复用现有的核心接口体系，保障后端多 Agent 改造不受干扰。
- **双端并行验证**：在迁移阶段，Streamlit（8501 端口）与新前端（5173 端口）可同时运行，待新前端功能完整验收后再平稳下线旧界面。
