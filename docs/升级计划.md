# 多模态 AI Agent 框架升级计划（多 Agent 协作架构）

## 一、升级背景与目标

当前框架基于**单 Agent + 多模型调度**设计，由 Agent 核心状态机结合 TaskRouter 与 Router 完成从任务意图拆解到模型调用的全流程。

随着业务复杂度提高（如长文本润色、文生图、图生文、多模态链式协作、生成质量控制），单 Agent 承担的职责过重。本次升级目标是将系统演进为**多 Agent 协作系统（Multi-Agent Architecture）**：
- **职责单一化（SRP）**：将具体的业务生成与控制拆解到专业 Agent 中。
- **动态闭环（Agentic Loop）**：将原静态 Evaluator 升级为具备审查与反思打回能力的 Reviewer Agent。
- **资产高复用**：最大化复用已有稳固基建（LLMClient、Builder、Storage、RedisTaskManager/Worker）。

## 二、架构演进与资产盘点

### 2.1 模块演进对照表

| 已有能力 | 对应模块 | 在多 Agent 架构中的定位 | 改造说明 |
| :--- | :--- | :--- | :--- |
| **任务拆解、状态机驱动** | `Agent` + `TaskRouter` | **Orchestrator** 调度核心 | 状态机由 `ROUTING/CALLING` 升级为 `DISPATCHING/COLLECTING` |
| **模型注册、能力匹配、备选切换** | `Router` | **ModelRegistry** 下沉服务 | 保留作为模型层路由器，由具体 Agent 内部调用 |
| **角色与能力注册** | *(待新增)* | **AgentRegistry** | 注册与管理各 Agent 角色及其能力标签 |
| **通信与数据流转** | *(待新增)* | **MessageBus** | 轻量级消息与产物交换通道，支撑任务派发与结果回收 |
| **HTTP 调用、多模态支持** | `LLMClient` | **基础 I/O 通道** | 原封不动复用，由各专业 Agent 共享 |
| **响应拼装** | `Builder` | **最终产物拼装** | 原封不动复用，服务于 Orchestrator 最终输出 |
| **会话记忆** | `Memory` | **分层记忆** | 扩展支持 `agent_id` 维度隔离与上下文按需注入 |
| **数据持久化** | `Storage` | **持久化存储** | 新增 `agent_messages` 表，记录各 Agent 的交互细节 |
| **质量审计** | `Evaluator` | **Reviewer Agent** | 升级为审查 Agent，支持规则审查、LLM 质检与反思打回 |
| **异步任务、Worker** | `RedisTaskManager` + `Worker` | **异步任务引擎** | 原封不动复用，支撑高耗时任务排队与执行 |

| Agent 角色 | 核心职责 | 匹配场景 | 内部使用能力/模型 |
| :--- | :--- | :--- | :--- |
| **Orchestrator** | 接收请求、解析意图、制定 DAG 执行计划、向专业 Agent 派发任务、汇总结果 | 全场景总控 | TaskRouter、AgentRegistry、MessageBus |
| **Writer Agent** | 文本生成、文案撰写、多语言翻译、长文摘要、Prompt 优化 | 场景 1、场景 3 | `text-generation`, Qwen 系列模型 |

| **Reviewer Agent** | 规则校验、敏感性审查、事实核查、质量评估、反馈重试触发 | 场景审计与质量把控 | 规则引擎 + `text-generation` 评估 Prompt |

## 四、核心新增与改造模块规范

### 4.1 通用 Agent 基类 (`BaseAgent`)
所有专业 Agent 继承自 `BaseAgent`，拥有统一的生命周期与调用协议：
```python
class BaseAgent(ABC):
    def __init__(self, name: str, router: Router, llm_client: LLMClient):
        self.name = name
        self.router = router
        self.llm_client = llm_client

    @abstractmethod
    def execute(self, message: AgentMessage, context: TaskContext) -> AgentResponse:
        """执行具体任务并返回标准化响应"""
        pass
```

### 4.2 双层注册体系：AgentRegistry 与 Model Router
- **上层：AgentRegistry**
  - 供 Orchestrator 寻址。
  - 根据子任务的 `capability` 查找对应的专业 Agent（例如 `text-generation` -> `WriterAgent`；`image-generation` -> `ImageAgent`）。
- **下层：Router (ModelRegistry)**
  - 供具体 Agent 使用。
  - 负责在模型池中挑选适配的物理大模型（如主模型、备选模型故障转移降级）。

### 4.3 消息通信与产物交换 (`MessageBus` & `Artifact`)
- **拓扑结构**：星型架构（Hub-and-Spoke），由 Orchestrator 集中协调，避免去中心化广播带来的不可追踪问题。
- **数据流与工件传递（Artifacts）**：
  ```python
  class Artifact:
      type: str          # "text" | "image" | "file"
      content: str       # 文本内容或媒体 URL
      metadata: dict = {}

  class AgentMessage:
      task_id: str
      step: int
      sender: str
      receiver: str
      prompt: str
      artifacts: list[Artifact] = []

  class AgentResponse:
      status: str        # "SUCCESS" | "FAILED" | "NEED_REVISION"
      output_text: str
      artifacts: list[Artifact] = []
      issues: list[str] = []
  ```
  在多模态链式任务中（如 Image 生成图片 -> Writer 根据图片写文案），Orchestrator 提取前一步的 `artifacts` 并自动作为输入注入下一步 Agent。

### 4.4 记忆（Memory）按 Agent 隔离
- 在 `Memory` 中增加 `agent_id` 作用域：
  - `Writer Agent` 关注长文本历史与对话上下文。
  - `Image Agent` 只保留当前的视觉 Prompt 与参数约束，避免冗余对话历史污染画面提示词。
- 提供公共上下文共享与私有上下文隔离机制。

### 4.5 持久化存储（Storage）扩展
在 SQLite 中新增 `agent_messages` 表，记录多 Agent 交互痕迹：
```sql
CREATE TABLE IF NOT EXISTS agent_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id TEXT NOT NULL,
    session_id TEXT NOT NULL,
    from_agent TEXT NOT NULL,
    to_agent TEXT NOT NULL,
    step INTEGER DEFAULT 0,
    message_type TEXT NOT NULL,
    content TEXT NOT NULL,
    artifacts TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 4.6 Reviewer Agent 的闭环控制与防死循环
- **审查机制**：支持“规则快筛 + LLM 深度评估”。
- **反思重试（Reflection Loop）**：当 Reviewer 判定质量不达标时，返回修改建议并通知 Orchestrator 触发重试。
- **容错防死循环**：
  - 严格限制单次任务最大重试次数 `max_retries <= 2`。
  - 超过阈值后自动走降级逻辑（标记告警并输出当前最优结果），防止过度消耗 Token。

## 五、典型协作场景流程

### 场景 1：单步文本问答 / 翻译
1. 用户输入 -> Orchestrator 接收。
2. TaskRouter 解析为 `single_text`。
3. Orchestrator 调度 `Writer Agent`。
4. `Writer Agent` 调用 Qwen 完成生成。
5. Orchestrator 调用 `Reviewer Agent` 快速审查通过，Builder 拼装输出。

### 场景 2：单模态文生图
1. 用户输入 -> Orchestrator 接收。
2. TaskRouter 解析为 `single_multimodal`（生图）。
3. Orchestrator 调度 `Image Agent`。
4. `Image Agent` 调用 Wanx 模型生成图片 URL 并包装为 `Artifact`。
5. Reviewer 校验图片有效性，返回最终结果。

### 场景 3：多模态复合任务（生图 + 深度配文）
1. 用户输入：“生成一张赛博朋克城市图，并写一段科幻背景故事”。
2. TaskRouter 输出多步骤 DAG 计划：
   - Step 1: `image-generation`（Image Agent）
   - Step 2: `text-generation`（Writer Agent，依赖 Step 1 产物）
   - Step 3: `review`（Reviewer Agent）
3. Orchestrator 先调度 `Image Agent` 生成图片 `Artifact(image_url)`。
4. Orchestrator 将 `Artifact(image_url)` 作为上下文输入派发给 `Writer Agent`。
5. `Writer Agent` 结合图片与用户要求创作文案。
6. `Reviewer Agent` 进行文图一致性与文本质量审查。
7. 最终交付用户。
