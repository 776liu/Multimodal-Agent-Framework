# 毕设总方案：基于多 Agent 协作的多模态视频生成系统

> 本文档是项目的总纲，整合《升级计划》《前端优化方案》与视频生成能力落地的完整路线，
> 按毕设答辩导向组织：定位 → 架构 → 分阶段实施（含验收标准）→ 主动降级 → 实验设计 → 论文结构 → 风险对策。

---

## 一、选题定位

### 1.1 题目建议（二选一）
1. 《基于多 Agent 协作的多模态视频生成系统设计与实现》（稳妥版）
2. 《面向异构时长任务的多 Agent 编排系统设计与实现——以 AI 视频生产流水线为例》（突出差异版）

### 1.2 三个答辩差异点（回答"和 AutoGen 有什么区别"）
1. **异构时长任务编排**：秒级文本/图片任务与分钟级视频任务在同一状态机体系下的调度隔离（双队列双 Worker）；
2. **能力感知路由**：带图请求必达 VLM、协议错误与超时区别对待的预算感知降级；
3. **面向演示可靠性的工程设计**：视频本地化落盘、分阶段进度可见、分层审计闭环。

### 1.3 论文叙事主线
**故障驱动的架构演进**——三段真实故障，每段都有报错码、call_chain 日志与修复 diff：
| 事件 | 暴露的问题 | 演进的设计 |
| :--- | :--- | :--- |
| VLM-400（纯文本模型看图被拒，三级降级才救回） | 路由只看能力标签不看请求形态 | 能力感知路由 |
| Markdown 围栏包裹 JSON，PLANNING 全灭 | LLM 输出不可控 | 输出容错与结构化约束 |
| 单 Worker 被长任务冻结 | 异构时长任务无隔离 | 双队列双 Worker |

## 二、目标架构

```
                     ┌──────────────────────────┐
   用户 / 前端(React) │  轮询进度(预留SSE) + 结果   │
                     └────────────┬─────────────┘
                                  │
                     ┌────────────▼─────────────┐
                     │       FastAPI 网关        │
                     │  submit / status / 静态托管 │
                     └──────┬─────────────┬─────┘
                            │             │
                  ┌─────────▼───┐   ┌─────▼────────┐
                  │ 快车道队列    │   │  慢车道队列    │
                  │ text/image  │   │    video     │
                  └─────────┬───┘   └─────┬────────┘
                            │             │
                     ┌──────▼─────────────▼──────┐
                     │   Orchestrator（状态机）     │
                     │ PLANNING → DISPATCHING →   │
                     │ COLLECTING → AUDITING      │
                     └───┬─────┬─────┬─────┬─────┘
                         │     │     │     │
                   ┌─────▼┐ ┌──▼───┐ ┌▼────┐ ┌▼─────────┐
                   │Writer│ │Image │ │Video│ │Reviewer  │
                   │Agent │ │Agent │ │Agent│ │Agent     │
                   └───┬──┘ └──┬───┘ └──┬──┘ └┬─────────┘
                       └───────┴────┬───┴─────┘
                                    │
                     ┌──────────────▼───────────────┐
                     │ Router(能力匹配) → LLMClient   │
                     │ text同步 / image同步 / video异步│
                     └──────────────────────────────┘
```

> 阶段 1 时 Agent 类尚未拆分，由现有 `Agent` 承担全部逻辑（baseline）；阶段 2 按上图拆分。

## 三、分阶段实施（每阶段末设硬性验收点）

### 阶段 0：填坑与加固（约 3 天）
| # | 工作项 | 说明 |
| :--- | :--- | :--- |
| 0.1 | `agent.py` 的 `output_type` 三元表达式改映射表 | 现状 `text-generation` 之外全走 image 分支，`video-generation` 会被错送 |
| 0.2 | Router 降级按物理 `model_name` 去重 | 修复同模型多注册名重复撞墙 bug |
| 0.3 | 带图请求能力感知路由 | `image_url` 非空 → 只从具备视觉能力模型选择；config 给 Qwen3-VL 加 `image-to-text` 标签 |
| 0.4 | 前端轮询超时参数化 | `taskStore` 的 120s 硬编码 |
| 0.5 | 修复环境性失败单测 | 补 `config/app.yaml` 测试配置，让 pytest 全绿 |

**验收**：pytest 全绿；链式图文任务（生图→描述）一次直达 VLM，call_chain 零降级。

### 阶段 1：视频能力落地（单 Agent baseline，约 1.5 周）
| # | 工作项 | 说明 |
| :--- | :--- | :--- |
| 1.1 | `LLMClient` 增加 video 分支 | `POST /v1/video/submit` → `requestId` → `GET /v1/video/status` 轮询（3~5s 间隔）；**HTTP 超时保持短（30s）**，编排层 deadline 15min |
| 1.2 | `config/model.yaml` 增视频模型 | `Wan2.2-T2V-A14B`（文生视频）+ `Wan2.2-I2V-A14B`（图生视频，链式场景） |
| 1.3 | TaskRouter prompt 升级 | 新增 `video-generation` 能力与"脚本→分镜→视频"few-shot 示例（注意 JSON 容错已具备） |
| 1.4 | 双队列双 Worker | 快车道 `agent:queue`（text/image）、慢车道 `agent:queue:video`，各自独立线程；`RedisTaskManager` 已支持 `queue_key` 参数 |
| 1.5 | 任务进度可见 | Redis 任务 hash 增加 `stage/progress` 字段（InQueue/InProgress/已等待时长），`GET /api/task/{id}` 透出 |
| 1.6 | 预算感知降级 | 视频任务：协议错误（401/400）才降级、超时不降级、最多重试 1 次 |
| 1.7 | 视频本地化落盘 | 完成后下载至 `data/videos/`，FastAPI `StaticFiles` 托管，前端拿本地 URL（解决签名 24h 过期） |
| 1.8 | 前端视频渲染 | `ChatBubble` 支持 `<video>`（海报帧 + 灯箱），进度显示"视频生成中，已等待 X:XX" |
| 1.9 | Redis TTL 调整 | 视频任务 expire 拉长，或明确以 Storage 持久化为准 |

**验收**：一句话"生成赛博朋克城市视频并配文案"全链路 SUCCESS；视频任务进行期间，另一会话文本任务 P95 < 5s（不被冻结）。

### 阶段 2：多 Agent 改造（论文主体，约 2 周）
| # | 工作项 | 说明 |
| :--- | :--- | :--- |
| 2.1 | 数据契约 | `BaseAgent` 抽象基类（`execute(message, context) → AgentResponse`）、`AgentMessage` / `Artifact` |
| 2.2 | AgentRegistry | capability → Agent 静态映射表（主动降级，见第四节） |
| 2.3 | WriterAgent / ImageAgent 迁移 | 逻辑从 `Agent.run` 拆出，**先建等价性测试再迁移** |
| 2.4 | VideoAgent | 封装 submit/poll/落盘/预算降级——论文第一个完整专业 Agent |
| 2.5 | ReviewerAgent | 规则审计（时长/分辨率/URL 可达/文本长度）+ 可选抽帧 VL 审计（**提前验证答辩机 ffmpeg 可用**） |
| 2.6 | Orchestrator | 改造现有 Agent：DISPATCHING / COLLECTING / AUDITING 状态流转，维护 `step_outputs` 工件传递 |
| 2.7 | 存储与记忆扩展 | Storage 新增 `agent_messages` 表；Memory 增加 `agent_id` 命名空间 |
| 2.8 | 集成测试 | 三类场景端到端：纯文本 / 单视频 / 生图→图生视频→文案链式 |

**验收**：多 Agent 路径与阶段 1 baseline 产出等价；审计记录入库可查；前端观测面板显示各 Agent 状态。

### 阶段 3：实验、演示与论文（约 1.5 周）
见第五节实验设计；同时录制**备份演示视频**（含降级场景），论文初稿完成。

## 四、主动降级决策表（防烂尾，每条都配论文说辞）

| 原计划 | 降级为 | 论文说辞 |
| :--- | :--- | :--- |
| SSE 实时推送 | progress 字段轮询 | "设计并预留 SSE 升级路径，当前轮询满足演示需求" |
| MessageBus 独立模块 | 进程内 dispatcher | "接口已抽象，单机部署无需跨进程通信" |
| AgentRegistry 动态注册发现 | 静态映射表 | "当前角色规模小，静态注册足够，接口预留扩展" |
| 四个 Agent 全量拆分 | Video/Reviewer 先拆，Writer/Image 复用逻辑 | 分步迁移 + 行为等价验证，降低回归风险 |

## 五、实验设计（全部可量化，映射三个差异点）

| 实验 | 验证目标 | 方法 | 指标 |
| :--- | :--- | :--- | :--- |
| E1 降级恢复延迟 | 差异点 2 | 注入主模型 500/超时（文本任务 n≥50） | 恢复耗时、最终成功率 |
| E2 双车道隔离性 | 差异点 1 | 视频任务运行中，对比单 Worker vs 双 Worker 下文本任务 P95 | P95 延迟 |
| E3 拆解容错 | 叙事主线 | Markdown 围栏剥离前后各跑 n=50 真实输入 | JSON 解析成功率 |
| E4 能力路由命中率 | 差异点 2 | 带图请求一次通过率（修复前 vs 修复后） | 一次通过率、平均降级次数 |
| E5 审计有效性 | 差异点 3 | 规则审计 vs 抽帧 VL 审计，小样本人工标注 | 检出率/误报率 |

## 七、风险与对策

| 风险 | 概率 | 对策 |
| :--- | :--- | :--- |
| 视频 API 变慢/限流 | 高 | deadline + 进度提示；演示用预生成备份视频 |
| 演示机 ffmpeg 缺失 | 中 | 阶段 2 提前验证；审计可降级为纯规则检查 |
| Agent 拆分引入回归 | 中 | 先建等价性测试再迁移；Video/Reviewer 优先拆 |
| 时间不够（最高风险） | 高 | 按阶段验收推进；阶段 2 可裁剪 Writer/Image 拆分而不伤论文主线 |
| 查重/与开源框架撞车 | 中 | 叙事重心放在三差异点；主动划界"不采用通用框架的原因" |
